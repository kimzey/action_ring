ActionRing

Turn any multi-button mouse into a context-aware radial command hub on macOS.
v1.0.0 macOS 14+ Swift 6 · SwiftUI + AppKit No dependencies Zero network calls
⊕ Figmarelease to cancel

Hold a configured mouse button and the Action Ring fades in at your cursor. Drag toward an action; that wedge highlights. Release to fire it — release in the center to cancel. The ring's contents switch automatically with the focused app, and it works with any mouse because it reads the normalized macOS HID stream via CGEventTap, not a vendor driver.

Features

  • Universal mouse trigger — capture any mouse button (side buttons recommended) via CGEventTap.
  • Context-aware profiles — the ring auto-switches per focused app, with category and default fallbacks.
  • Glassmorphic radial UI — translucent wedge segments, a glass center hub showing the app + selected action, spring animations; 4/6/8 slots, three sizes.
  • 11 action types — keyboard shortcuts, app launch, URLs, system actions, shell/AppleScript, Apple Shortcuts, text snippets, file open, multi-step workflows.
  • Fullscreen-aware — suppressed over borderless-fullscreen games.
  • Button recording — set the trigger by pressing the button on your mouse.
  • Preview mode — see the ring respond to your cursor with no permission required.
  • Privacy-first — zero network calls; reads only the focused app's bundle id + name.

Install & first run

1. Build the app

cd action_ring
make bundle            # → ./ActionRing.app  (release, ad-hoc signed)
open ActionRing.app

ActionRing is a menu-bar app (no Dock icon). Look for the ⊕ icon at the right of the menu bar.

2. See it immediately — no permission needed

Menu-bar icon → Preview Ring, or launch with the flag:

open ActionRing.app --args --preview

The ring appears and follows your cursor for a few seconds so you can confirm the look and tracking.

3. Grant Accessibility (so the trigger works)

The trigger needs an event tap, which requires Accessibility:

  1. System Settings → Privacy & Security → Accessibility
  2. Enable ActionRing
  3. If the ring doesn't arm, quit and reopen ActionRing.

This is the only permission ActionRing requests.

4. Use it

hold the trigger button   →  the ring appears at your cursor
drag toward a slot        →  that wedge highlights (35px dead zone in the middle)
release                   →  the highlighted action fires
release in the center     →  cancels

Default trigger is Button 4 (the side/thumb button) so left/right clicks keep working. Change it in Settings (menu-bar icon → Settings…), including a Record from mouse button.

How it works

trigger DOWN ─► (unless a fullscreen game is frontmost)
                 show ring at cursor, populated from the active app's profile
   move ───────► a 120 Hz cursor poll highlights the wedge under the cursor
trigger UP ───► hold-release fires the highlight; a quick tap leaves the ring
                "sticky" so a second click fires it.  Center = cancel.

Two gestures: hold the trigger → drag → release to fire; or quick-click to open a sticky ring → move → click again to fire (center = cancel, auto-closes after 6s).

Privacy

ActionRing makes zero network calls in v1.

It reads the focused app's bundle identifier and localized name only — never window titles, document paths, keyboard input, or window/document contents. CGWindowList is queried for window bounds and owner PID only. Profiles & settings are plain JSON under ~/Library/Application Support/ActionRing/.

Custom profiles

Built-in profiles cover common apps. Custom profiles live in:

~/Library/Application Support/ActionRing/profiles.json

Each profile maps a bundleId (or category) to up to 8 slots; each slot has a position (0–7), label, SF Symbol icon, color, and a RingAction. Settings live in settings.json and the universal fallback in default.json. (A visual editor is on the roadmap.)

Development

make build      # compile all targets (debug)
make check      # run the invariant checker (no Xcode needed)  → 29 checks
make test       # XCTest suite (requires a full Xcode toolchain)
make run        # run from .build (prefer `make bundle` for Accessibility persistence)
make bundle     # assemble + ad-hoc sign ActionRing.app (release)
make install    # bundle + copy to /Applications
make clean

ARCheck exists because XCTest/Testing aren't available with Command Line Tools only; it runs the same core invariants and exits non-zero on failure, so it works anywhere Swift compiles.

Troubleshooting & FAQ

The ring doesn't appear when I hold the button.

Grant Accessibility (System Settings → Privacy & Security → Accessibility → ActionRing) and reopen. Confirm the trigger button in Settings matches a button your mouse has — use Record from mouse. Try Preview Ring first to confirm rendering.

The ring shows but doesn't react to dragging.

Fixed: tracking is driven by a 120 Hz cursor poll. Make sure you rebuilt (make bundle).

Triggered ring looks faint/old, but "Preview Ring" looks great — and the trigger won't fire even with Accessibility enabled.

You're running an old instance (it still holds the grant + shows the old UI) while the rebuilt app isn't trusted. Each ad-hoc make bundle changes the code hash, so macOS treats it as a new app. Reset cleanly:

killall ActionRing        # stop every old instance
make reset-perms          # clear stale grants
make install              # build → /Applications → open fresh
# then enable ActionRing in Accessibility

The menu-bar status tells the truth: ● Ready — trigger is live, ▲ Permission OK — click "Re-arm", or ○ Needs Accessibility.

To stop the grant resetting on every rebuild, run make cert once to create a stable self-signed "ActionRing Dev" identity; make bundle then signs with it and the grant persists.

My side button still triggers "Back/Forward".

ActionRing suppresses the trigger press, so it shouldn't. If another tool (Logitech Options+, etc.) also binds that button, disable its binding.

Does it work on a trackpad / Magic Mouse?

The trigger needs a distinct mouse button. A trackpad has none, so use a multi-button mouse.

Is anything sent over the network?

No — v1 makes zero network calls.
